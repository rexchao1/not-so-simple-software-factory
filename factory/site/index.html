How it works

From a saved task to inspectable code.

Factory coordinates the work around coding agents without hiding the Git repository or the machine doing the execution.

  1. 01

    Define

    Save the prompt, runtime, repository scope, schedule, and execution settings.

  2. 02

    Dispatch

    Create one Run and route each repository Session to an eligible Worker.

  3. 03

    Execute

    Run Pi, Codex, or Claude Code inside a fresh Git worktree with bounded concurrency.

  4. 04

    Inspect

    Review events, output, failures, branches, retries, and retained work from one browser.

Built for real software work

Coordination without surrendering control.

↻

Repeatable by default

Tasks preserve prompts and execution settings. Run them now, on a schedule, or across many repositories.

⌘

One operational surface

See queued, active, blocked, failed, and completed work without reconstructing state from terminals.

⑂

Git-native isolation

Attempts use independent worktrees. Failed and unpublished work stays available for inspection.

⌁

Fleet-aware execution

Workers advertise healthy runtimes and capacity from local machines or authenticated remote VMs.

◎

Local-first authority

The browser and operator API stay on loopback. Repository data and runtime credentials stay on Workers.

◫

Honest observability

Attempts, leases, events, results, cancellation, and retained work remain explicit rather than magical.

Architecture

A small control plane.
Workers do the work.

Factory keeps durable coordination in a Go service backed by SQLite. Workers poll for eligible work, prepare repositories, supervise agents, and report bounded results.

Developer preview

Useful now. Still changing.

Factory already runs durable, scheduled coding work across Worker fleets. Compatibility-breaking changes are expected while the product moves toward ordered software pipelines and a software-work graph.

Available today

  • Tasks and scheduled Runs
  • Multi-repository execution
  • Pi, Codex, and Claude Code
  • Local and remote Workers
  • Run table, list, and Kanban

Active direction

  • Ordered agent stages
  • Repository pipeline tracks
  • Software-work graph
  • Clear needs-you states
  • Delivery evidence

Run it locally

Your agents. Your machines.
One control plane.

Factory is open source under the MIT license. Start with one local Worker, then add machines when the work demands it.

terminal
$ git clone https://github.com/owainlewis/factory.git
$ cd factory
$ just build
$ mkdir -p ~/.factory
$ cp examples/worker.toml ~/.factory/worker.toml
$ just run
